# 恢复停止请求超时修复

## 行为

刷新恢复的对话点击停止后，原路径直接等待 stop 请求，服务端或网络一直不返回时无法结束等待。本次为请求增加 500ms 截止时间，即使底层忽略 AbortSignal 也能结束等待。超时后与普通停止共用原运行核实：最多两次、间隔 300ms、总预算 5 秒，核对 run_id 与 message_id。

取得终态则保留其真实状态（包括 completed/failed），未取得则显示“停止结果未确认”，终止本地接收但不推定后台已取消。正常 cancelled=false 和即时异常保持既有缓冲回放行为。核实受原控制器与认证身份约束，卸载取消等待，迟到响应不能结束下一轮。

## 本地证据

- 新增 7 条页面回归在修复前失败；修复后页面 83 项通过。
- 普通发送、控制器注册表、stream reducer、状态行相关 4 文件 190 项通过。
- 有界核实 helper 16 项通过，含无限挂起、父取消、身份不匹配及迟到结果。
- 触及文件 ESLint、生产构建、diff 检查通过；构建不包含全仓类型检查。
- 独立只读审查未发现新增可达 P0/P1。

用户本次授权修复、PR、CI、合并；明确暂缓真实页面验收。上述结果是本地模拟回归，不是线上故障复测。合并会触发既有 dev 自动发布流程。
