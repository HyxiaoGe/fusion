# 语义正则迁移第五阶段：天气返回事实校验补修

## 真实 API 触发证据

- 第四阶段已部署到 dev 并核对 API 台账与运行镜像。原句“明天深圳市天气怎么样？我上午骑行主要想避雨，能确认上午不下雨吗？”的 run `22521c1aacd94afd856188db6179d389` 中，`weather_forecast` 成功；模型候选明确指出本轮只有白天／夜间预报，无法确认上午是否下雨。最终答案却因 `weather_fact_mismatch` 退回四天结构化预报，没有回答上午能否确认。
- 逐句核对同一候选与持久化 `weather_results`：`北风1—3级` 的长横线被解析成 `1`；“是否下雨无法在这种时间粒度上确认”中的疑问词被当作下雨事实；“高低温是33℃/26℃”首个值被按低温核对；“气温和风力”中的“和风”被误认为风况。四处均是校验器词面解析误拦。

## 最小修复与反例

- 统一风力范围中的横线写法，仍与返回的风向和风力逐值核对；错误的 `1—5级` 继续拒绝。
- 仅将“是否／能否／会不会／能不能”引出的疑问部分视为疑问，保留后续肯定断言的事实校验。支持“是否下雨，无法确认”和问号断句；“是否下雨：会下雨但无法确认”仍拒绝。
- “高低温”成对数值按高、低温核对；后面另有明确“最高”时以该标签为准，错误的“最高26℃”仍拒绝。排除“和风力”误匹配。
- 第四阶段原始模型候选与持久化结果在本地新校验器重放，得到 `is_valid=True, reason_code=ok`。这只证明该候选不再被误拦，真实 API 效果必须在 dev 部署后核对。
