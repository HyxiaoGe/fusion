# 工具失败恢复修复

## 原问题与实现

真实失败 Run `459accfa1afb463a98e6e8285570713e`（香港三天天气）只有 weather_forecast 一次调用，返回失败后 stop，工具失败但Run completed。预算64/200/1800已生效，因此这不是预算问题。

- 高德上游 `UNKNOWN_ERROR` 仍是实际提供方失败；客户端现保留有界安全错误详情供工具详情和不可信 Observation 使用，不将其猜成参数错误。
- 外部能力任务追加现有可选搜索/网页读取，主工具与初始计划要求保持，缺少替代能力不禁用主工具；前后端能力记录上限同步为三个主工具和两个联网工具。
- 模型上下文明确专用工具优先、失败后以原任务为目标选择其他可用工具。执行期记录真实失败和成功网页内容身份；模型过早stop且仍有未尝试工具时有一次可观测修复轮。计划增加恢复步骤仍走原绑定与执行约束。
- 失败后延迟候选输出，避免先流出放弃回答再继续。无成功产品卡片时，真实成功网页内容与有效显式引用允许保留模型答案；失败/空网页/只有链接/虚构引用不放行。已有产品卡片继续原事实校验。所有途径无证据时诚实收尾并标记incomplete，避免错误completed和无关航班等兜底。

## 验证边界

独立审查发现普通MCP失败未延迟输出、无证据提前完成两个关联缺口，已补修并复审无可达P0/P1。取消及服务器预算终态不被恢复重新打开。

集成隔离回归实际经过请求路由、driver、tool_round、天气和搜索处理器及终态持久化接口；外部LLM/MCP/搜索与持久化依赖模拟。覆盖天气UNKNOWN_ERROR→早停被抑制→搜索成功→有引用回答completed，以及替代搜索空结果→incomplete。它不能替代真实环境验收。

前端轨迹模块218项测试、production build通过；静态和差异检查通过。路由fixtures只同步公告工具和提示段落，主工具、实际调用要求和负例保留。新增证据/路由/集成用例均使用unittest兼容形式进入现有CI。
