# Issue #129：中文否定授权词边界回归（2026-09-23）

时间按 Asia/Shanghai。基线为合并 #128 后的 `master@e1f3c7f5`，其中 #129 相关否定解析与 issue 写明的 `6256541a` 相同。本报告区分代码阅读、本地执行、真实页面和发布身份；现阶段的候选代码仍在本分支，不能把本地测试写成 dev 页面已修复。

## 先复现

用 `_extract_request_signals` 和发现路径实际调用的 `resolve_discovery_network_denials` 逐条运行 issue 正文的 13 句。11 句误判均复现：8 句“分别／个别／特别／区别 + 打开／阅读／访问／浏览／读取”给出 `(web=False, url=True, all=False)`，3 句“分别／个别／特别 + 搜索”给出 `(True, False, False)`；“请逐一打开…”和“请依次阅读…”仍为 `(False, False, False)`。两个入口返回同一结果。这是本地代码执行结果，不是页面调用事实。

修复前，新回归文件的 9 个普通复合词 × 6 个网络动词、原 13 句、每处正则和其他否定词扫描共 **77 failed、10 passed**；其中显式禁用用例已经通过。根因从代码阅读确认：六个 `_NEGATED_*` 正则里使用裸「别」；`_extract_web_request_object` 的去指令表也会从“分别搜索”中间剔除「别」。工具名两处正则另外允许否定词与工具名之间任意跨越 16 字符。

## 修改与边界

- 六个否定正则共用 `_CHINESE_NEGATION_PREFIX`。初版通过排除“分别／个别／特别”等常见复合词的词尾字处理「别」；2026-09-24 复审又发现“组别／职别／届别／派别／界别／科别”不在排除表里，于是改为句首、分隔符后或固定祈使修饰语后的前置上下文白名单。`_extract_web_request_object` 使用相同边界，保留普通搜索对象中的“分别”。`_VERIFIED_SOURCE_RE` 等语义正则未动。
- 两处工具名禁用把 `.{0,16}?` 改成明确的可选指令结构，保留“别用 web_search”“不要把 web_search 用于这次回答”“请勿在本次任务中调用 url_read”“禁止让模型调用 web_search”等显式禁用，同时不再把“不用功调用 web_search”“不用户调用 url_read”“不要紧调用 web_search”“不得不调用 url_read”“不可避免地调用 web_search”当成禁用。直接网络动词正则原本就未误判“不用功打开网页”“不用户读取网页”；这两句不能替代工具名分支的扫描。
- 另外用原 `#128` 基线与候选分别跑 352 条否定词 × 网络动作／工具名表达。两者输出逐项一致、**没有已生效禁用被撤销**；普通词的修正由独立负例矩阵核验。工具名分支保留原有否定词种类，没有借本次修复扩大硬禁用范围。
- 动态发现仍默认关闭；`requires_catalog_evidence`、`product_answer_validator.py`、③ 类语义正则均未改。六个 `_NEGATED_*` 加对象提取处共七个位置逐一有测试。否定仍为服务端硬约束，不依赖模型自觉。

## 2026-09-24 复审补验

Claude Code 在初版分支实测六句新的误撤权。修改前，本地新增矩阵在“请按组别打开这两项”即失败；修改后，六句原文和额外 12 个“X别”复合词 × 6 个网络动作均不撤权。审查指定的七句真禁用全部通过。原 #128 基线的 352 条禁用表达逐项对照 **0 差异**；原 33 条盲测仍 **14/33**，完整 47 条仍 **18/47**，逐行输出与基线一致。

白名单初稿出现了真禁用漏拦：原 #128 路径上，“我们别打开这个网页”“大家别搜索”“麻烦别访问这个站点”“这次别联网”“请帮我别读取网页”均会禁用相应工具；只用审查最初列出的前置词时，这五句均不触发禁用。用户明确同意扩充**封闭**的常用前置词集合后，以上五句与“能不能别搜索”“可不可以别搜索”“拜托别搜索”“不过别搜索”等常用表达均已加入定向测试。目标测试 **249 passed**，覆盖原有 92 条；相关路由、授权和发现测试 **985 passed、21 subtests passed**。另外两个测试分别因本机沙箱禁监听和 SQLite 无法建立 PostgreSQL JSONB 表而无法在本机通过，需由 CI 验证。Ruff、格式和 diff 检查通过。

封闭词表仍有已知边界，例如“小王别打开这个网页”在原 #128 代码中会禁用，当前规则不禁用；任意称呼或主语无法靠有限前置词完全覆盖。此类句子要在合并审查时明确讨论，不能把 352 条对照零差异解释为所有显式禁用无退步。本文不将目前候选版标为安全边界全量通过。

独立盲测 47 条没有 ② 类联网授权否定样本；18/47 零差异不构成本次修复有效证据。覆盖缺口已另记 [issue #131](https://github.com/HyxiaoGe/fusion/issues/131)，本 PR 不改盲测 fixture。
