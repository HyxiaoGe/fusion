# 语义正则迁移第七阶段：天气条件交由模型处理

## 改动依据

- 第四至第六阶段连续三次 dev 真实请求中，`weather_forecast` 均成功，模型候选均正确说明“上午是否下雨无法从昼夜预报确认”，但天气条件词面校验分别因风力横线、疑问范围及组合句式误拦，最终退回未回答避雨问题的多日事实兜底。第六阶段 run 为 `9412c969b5844686a3ee00a5d0b20d5e`。
- 产品结果模型已拿到结构化 `forecast_days`。本阶段移除天气状况、建议、风况描述和“是否下雨”疑问的本地语义匹配，让模型依据返回字段回答；仍核对行政区、明确日期、温度、风向风力及未返回的数值指标。天气提示词新增预报范围外日期的限制说明，并禁止未返回的降水量。
- 这意味着本地校验通过不能证明天气描述正确：例如返回“多云”时，单凭本地校验不会拦住“白天有雨”。相对日期与天气条件的组合也由模型负责，代码只在明确日期或可解析数值事实处验证范围。该风险必须以发布后真实模型回答和持久化结果对照判断，不能把目标测试当作验收。

## 本地验证

- 第四、第五、第六阶段的原始模型候选与各自持久化天气结果在本地新校验器重放，三条均得到 `is_valid=True, reason_code=ok`；重放只证明旧误拦解除。
- 独立只读复审发现“风景”触发裸“风”的新增误拦、“带伞／雨具”仅因词面不同而结果相反，以及移除能力词表后预警、积水、降水量的数值漏检。本轮已撤掉天气建议的相对日期词面门禁，并补充未返回的预警等级、积水与降水数值测试；对“没有湿度数据”等限制说明不再误拦。
- 天气校验目标测试 73 项通过；最终版本完整 unittest 3254 项通过、2 项跳过，额外 pytest 清单 241 项通过；架构、Ruff 全仓和改动文件格式检查通过。PR CI 仍须独立验证。
