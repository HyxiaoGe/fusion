## 动态发现默认入口的当前条件

代码阅读基线为 `1ba16d7`：前端普通发送只传 `plan_mode`、`task_mode`；后端只有 `options.dynamic_tool_discovery is True` 才走授权目录发现，否则调用旧包分类。发现路径不调用包分类器，`capability_resolution=None`，目录仅由已授权、具备 schema 和 handler 的工具构成。当前明确拒绝 Skill release pin、深度研究、续跑及不支持 function calling／联网工具的模型；`disable_tools`、Knowledge Grounded 也因无可用工具而不能走该入口。普通模式的部分事实义务仍由实验适配逻辑承接。

已取得的真实业务证据不能合成“全面通过”：历史显式发现运行 `b7fd4527` 有天气、高铁、行程产品块及完整日期回答；`cdf9b0b1` 有车次和部分天气结果，但 run 为 `incomplete`，最终说明苏州、南京天气未取到；PR #112 后另有发现、搜索、读取和带来源回答的有限页面路径。工具日志 success、Run completed、产品回答完整性分别判断。历史代码与原型报告中“未验收”的条目需按这些后续记录更新，但不能反过来宣布任意供应商和表达均已覆盖。

切换前的最小判据：

1. **执行一致性**：服务端授权目录是唯一上限；发现后 schema、handler、binding、计划允许集及公告同步，未加载可恢复、未授权拒绝，禁网与预算保持。现有离线覆盖仍需以生产授权集和实际故障路径核对。
2. **交付与恢复**：用少量固定、显式日期的真实业务场景核对有效结果、来源正文、空/失败结果、最终正文与产品块、刷新及取消；不再按调用次数或模型自述计成功。已通过的同一场景不重复采样。
3. **当前不兼容场景**：旧路径的 `verified_web` 包会装载 `verified-research` Skill，其固定版本、web_search/url_read 精确权限与来源核查义务目前没有独立承载；发现路径只会在 web_search 公告后注入通用工具使用规则。深度研究的阶段工具约束、续跑的历史策略与 Skill pin、禁工具、Knowledge Grounded、不支持 function calling／联网工具的模型也未兼容。它们迁移前只能沿明示的旧路径运行，不能把候选路径的异常当作兼容。场景门禁应依据显式任务/模型能力，不能再建一套自然语言分类。
4. **历史与回退**：旧 `package_id` 记录仍可读；新的发现快照不伪造 package；切换需可回退到旧路径且不改变进行中 Run。切换后按实际流量观察分类器调用是否下降，再逐项删除不用的旧分支。
