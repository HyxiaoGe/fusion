# 开发指引更新与验证

本次在 `master@1e4c397d` 基础上更新开发协作规则，范围为 AGENTS/CLAUDE、开发 skills、指引检查与本机全局入口。没有修改业务代码、CI workflow 或运行环境。

## 规则变化

- 根 AGENTS 维护共同的授权、执行与证据边界；应用 AGENTS 只补充后端/前端工程约束。CLAUDE 直接导航到共同约定，避免双份正文漂移。
- 开发、Git/发布、真实验收分为三个仓库 skills；下一步建议按主题检索当前证据，不固定读取所有历史或输出四段模板。
- 明确授权持续有效、独立工作继续、验证范围随影响面变化。保留用户文件保护、真实 Chrome 复用、环境变更授权与完成状态证据要求。
- 提供商接入改为当前 LiteLLM Proxy alias/目录架构；API 参考改从当前 router/schema 获取；流式诊断定位当前 stream 包；日志不再默认滤掉异常或声称某类错误均可忽略。
- 技术入口中的源码和文档使用可校验链接。扩展仓库检查覆盖全部开发 skills；保留敏感流正文读取限制、历史迁移范围及现有文档保留检查。
- 删除对固定措辞、所有入口重复包含同一组历史扫描命令的断言，改查实际导航可达性、权威入口及引用存在性。

## 独立场景检查

两名独立代理分别读取旧规则和新规则，使用相同场景只读核对文档及源码，不执行修改、远端调用或真实验收：

| 场景 | 新规则导出的执行与终点 |
|---|---|
| 侧边栏选中延迟，只到本地 | 先核对已有即时选中逻辑，必要时修复并做目标验证；不重复设计审批，不推送；无页面证据则保留页面缺口 |
| 新模型提供商，禁止远端配置 | 从 Proxy alias/目录判断是否需要适配；缺目标提供商时只暂停依赖该信息的实现，不恢复旧映射表，不调用真实模型 |
| 已授权推分支、PR 与 CI 修复，禁止合并 | 跟踪最新提交的 PR checks，按授权修复 CI，完成到 PR/CI；不合并、不部署 |
| 无 Chrome 标签，只调查断线 | 继续源码、测试阅读与已有脱敏状态调查，不启动服务、不创建会话；区分后台生成与客户端显示，保留客户端证据缺口 |

新规则的四个场景未发现要求越权、提前停止全部工作或误报完成的冲突。复核提出“修复本次引入的 CI 失败”可能被狭义理解，已明确用户授权覆盖全部 CI 阻塞时按该范围处理。

旧规则下代理也能通过核查源码作出大部分正确决策；本对照没有证明实际开发修复率或速度提升。它只验证指令可解释性、当前代码入口与授权边界。真实修复率、返工次数、耗时和错误完成声明，需要后续相同模型/设置下的实际开发任务继续观察。

## 本机安装与交付范围

全局 AGENTS 保留个人偏好、授权延续与工作区保护。三个全局 Fusion skills 使用符号链接指向本次仓库工作树中的版本，原文件已备份，避免继续维护两份实施规则。使用全局入口时优先用户指定工作树；父目录不是 Git 仓库时可从 skill 真实路径定位。

该工作树是当前全局技能的来源，在迁移链接前不能清理。规则合并后可将三个链接迁至保留的主工作树；迁移时核对源文件与安装清单。本机备份、源工作树与链接目标记录在此次本地安装的 `installed.json` 中。

本次交付到本地规则、安装和检查。没有推送、创建 PR、合并或触发部署。Superpowers 的插件卸载状态由 Codex 卸载工具单独确认，不从仓库正文中“无依赖”推断已卸载。

## Chrome 控制路径补充

用户指出既有登录态验收反复误用全桌面控制或启动新 Chrome，增加了人工介入。前版仅要求复用已有标签，没有明确扩展连接、标签绑定与故障处理步骤。本次在全局 AGENTS 固定网页交互的默认目标和控制范围，在项目根 AGENTS 指向验收 skill，由 skill 维护具体流程。用户明确指定其他浏览器或测试环境时仍遵循该选择。

- 官方[扩展文档](https://learn.chatgpt.com/docs/chrome-extension)说明如何接入日常浏览器的现有标签与登录态；[内置浏览器文档](https://learn.chatgpt.com/docs/browser)说明其配置与常用 Chrome 独立。当前 `cua_repl` 同时支持标签与原生应用，不能把工具名误解为只能执行全桌面操作。
- 本次调研已通过当前运行时枚举到 Chrome 扩展，并绑定用户已有 Fusion 标签，成功读取页面和登录状态。仅进行了连接与页面读取核验，没有创建浏览器进程、标签或业务会话，也没有重新运行收费模型。
- 新规则区分扩展内 Playwright/CDP 能力与独立自动化工具的启动流程；保留仓库自动化测试，禁止把隔离测试浏览器当作用户已有登录态的验收证据。扩展失败不转为原生桌面控制，也不复制 cookies 或启动新 profile 绕过。
- 本机全局验收 skill 仍通过既有符号链接读取本工作树，因此仓库修改与全局入口使用同一份正文。全局 AGENTS 的原文件另行备份后更新。
- 补充后 19 项仓库指引检查、验收 skill 的 quick_validate 与 diff 空白检查通过；全局 AGENTS 写入内容与准备稿一致，当前任务已收到更新后的规则。

连接实测证明当前路径可用，文档与结构校验不证明未来模型绝不会选错工具；本次没有模拟真实扩展断连，也没有把规则写成平台级工具禁用设置。
