# 停止确认与页面终态修复（2026-09-22，Asia/Shanghai）

## 问题与证据

PR #113 部署后真实 Chrome 验收失败两条：刷新恢复再停止，接口 cancelled=true、DB interrupted，但页面仍运行中；普通发送停止请求489ms被中止，DB已interrupted，页面仍需刷新。后台终态与页面即时终态是不同验收项。相关旧运行之后均已结束。

## 本轮行为

- 恢复流确认取消后立即 finalize 原运行，并写回原消息；后到的 running 水合不覆盖确认终态。按 controller、messageId、runId 隔离迟到响应。
- 恢复流无 taskId 不发会话级取消，保留接收并提示未确认。
- 普通停止仍保持原500ms请求预算，超时后独立读取原 run 轨迹快照并核对 messageId。最多两次读取，总核实预算5秒。观察到真实终态才更新；无法核实显示停止结果未确认，不冒充中断，也不继续递增计时。
- 本地确认状态与服务端运行状态分开；新一轮不继承旧停止确认。并行水合已取得终态时不得降回 running。
- 默认动态发现、后端接口和供应商超时设置未修改。

## 本地验证

新增普通停止/状态行6条回归先红；恢复路径3条回归先红；修复后目标测试通过。相关9文件359项通过，之后追加并行水合终态保护，发送hook87项通过（最终相关用例总数360）。触及文件ESLint通过，生产构建通过；构建未执行全仓类型检查。独立只读审查未发现当前新增且可达P0/P1，审查发现的终态降级P2已修并复核。

## 边界

恢复请求长期悬挂仍沿用原有等待行为，本轮没有为整个恢复流程重做超时与核实。没有task身份且本地停止后，不能声称后台取消成功。真实迟到网络的全部排列未穷举；单测不能替代发布后的真实点击、网络响应、持久化和刷新验收。dev发布与页面复测另记。
