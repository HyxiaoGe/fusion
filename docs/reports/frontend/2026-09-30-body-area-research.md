# 正文区域调研

日期：2026-09-30（Asia/Shanghai）。本轮范围为只读调研和建议，不修改产品代码、不发布、不新建真实会话或调用模型。

## 结论

优先把正文做成清晰、安静且有层次的阅读区域。现阶段最影响体验的是 Markdown 基础排版缺失，随后是过宽的行长、表格引用不一致、辅助面板与正文的视觉权重。玻璃材质适合操作入口与浮层；正文、表格和代码主体宜使用稳定的阅读底材。

Apple 官方 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 区分控件/导航的 Liquid Glass 与内容层材质，并建议克制使用；[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 也强调内容与功能层的清晰层次。这里是应用到 Fusion 的设计判断，不是把原生平台 API 或固定尺寸直接移植到 Web。

## 当前代码与构建阅读

当前工作树 `master@7bc191b23b1b40bf7b402df280097cbc72e64f46`，remote 为 `HyxiaoGe/fusion`。此前本地报告、执行台账补记和用户预览目录均保留。

1. **排版缺失根因**：`MarkdownRenderer.tsx:240` 使用 `prose` 类，但标题、段落、列表 renderer 仅返回原生标签；`tailwind.config.js` 只注册动画插件，package/lock 无 Typography，globals 无对应 `.prose` 规则。已有本地 `.next/static/css` 的五个产物均没有 `.prose` 选择器；预置 reset 会让标题继承字号/字重、清零 margin 并移除列表标记。构建阅读与真实 computedStyle 相符。
2. **宽度已有分层**：`ChatMessage.tsx:75` 的回答外壳最大 96rem；`AssistantResponseStack.tsx:74`、`:105` 的推理/状态和正文/依据最大 72rem；结构化结果位于两个限宽容器之外。改动应利用已有层次，避免把所有结果统一挤进一个窄气泡。
3. **表格引用根因**：`MarkdownRenderer.tsx:42` 把 `[n]` 转为 `⟦n⟧`；p/li/strong/标题会调用引用渲染，`:202`、`:207` 的 th/td 没有这一处理，导致占位符留在表格。普通表格已有横向滚动容器和完整网格边框，缺少独立表头底色。
4. **代码块边界**：`markdownCodeComponents.tsx:12` 解包 pre，`:22` 仅有 `language-*` 时进入 CodeBlock。因此没有语言声明的 fenced code 会走行内 code 分支。此项只有代码阅读证据，本轮未在真实页面造样本。`CodeBlock.tsx:180` 的行号没有顶部 padding，`:196` 的正文 pre 有 p-4，需要核对基线；现有复制、语言、行数、折叠功能已经实现，不应再建一套。
5. **辅助信息层次**：正文之前已有推理、活动、轨迹状态、工具结果和回答依据。`AnswerEvidence.tsx:112` 展示带边框的依据区和固定宽度来源卡片；来源侧栏与编号映射已存在。适合降低常态视觉重量、统一入口与状态，不应抹掉已使用/候选等语义。
6. **消息操作可见性**：`MessageActions.tsx:18` 在桌面仅依赖 group-hover 显现，没有 focus-within 显现；键盘聚焦存在不可见操作风险。这是代码阅读判断，本轮未做完整 Tab 顺序验收。用户消息操作区也有同类规则。
7. **用户文本展示**：`UserMessage.tsx:169` 在普通 div 渲染文字，缺少保留换行和长串断行样式。应保留纯文本语义，无需改成 Markdown；真实多行页面展示本轮未单独验证。
8. **滚动已有行为**：`ChatMessageList.tsx:302` 已支持主动上滚退出跟随、回到底部恢复跟随，ResizeObserver 覆盖内容高度变化。排版后需要回归实际滚动位置；没有理由在本轮视觉优化中重新设计 SSE、Redux 或持久化。

## 建议实施顺序

| 优先级 | 范围 | 预期改善 |
| --- | --- | --- |
| 第一批 | 正文专属排版 CSS、标题/段落/列表；表格引用处理 | 恢复阅读层级与编号，使表格和段落引用一致。无需为此升级 Tailwind 或新增依赖。 |
| 第一批 | 正文行长与留白、表格表头/行分隔、代码块与行号 | 普通正文更容易追行；宽表格保留独立横向滚动，工具结果仍可使用更宽布局。 |
| 第二批 | 来源/推理/状态入口、复制/重试工具条、用户文字换行 | 辅助信息易查而不抢正文，鼠标和键盘操作都可见。 |

原型起点建议：正文 15–16px、约 1.7 行高，段间距 12–16px，章节间距 24–32px；普通段落尝试约 760–840px 的阅读宽度，宽表格/代码与结构化结果单独评估。以上是待对比的设计参数，不是已验证最佳值或 Apple 固定规范。

第一版应采用现有真实回答对比，优先确认“密度、行长、标题层次”再发布；避免整段正文堆叠透明卡片、持续高光或浮动动画。此前用户已接受的控件边缘高光与交互反馈继续作为视觉一致性的参照。
