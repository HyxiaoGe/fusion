# Agent loop 可靠终止与输出归因

## 目标与授权

用户已确认进入开发。首批完成三个已复现的可靠性修复，以及模型候选到实际输出的归因；交付到隔离分支的代码、自动化验证和独立审查。保留本地 prompt、自实现循环和现有业务策略，不引入框架、数据库迁移、全量输入快照或新的观测服务。不启动本地服务，不推送、创建 PR、合并或部署。

基线：`ba6e108a080fb9c0ebe809be1d3585c1a65c2b86`，已核对远端 master。

## 可靠性契约

1. 服务端工具执行前后 checkpoint，以及取消/失败收尾，应保存本轮真实产生的结构化内容块。客户端 partial 更新继续禁止伪造工具结果；现有 generation_task_id 和授权校验保留。
2. 同批并行工具中任一子任务抛出控制流异常时，取消并等待其他本地任务清理，然后保留原异常。普通取消、成功结果顺序和成功签名去重不回归；不声称能撤销已经到达外部系统的操作。
3. max_steps、max_tool_calls 或 timeout 触顶后，有产品结果但计划未完成时仍应有基于现有结果的正文和未完成说明。终局不得回到补计划、修参或新工具执行分支，limit_reason 和最终 limit_reached 语义保留；不把待办伪装成成功。

## 输出归因契约

复用现有事件账本和身份，将实际 LLM round 的正文候选处置记录为 emitted（已输出）、suppressed（未采用）或 replaced（已改写/替换），附处理原因、输出来源以及实际输出块的关联信息。suppressed 的原因须区分从未发布与发布后撤回，界面不得把已撤回描述为从未展示。来源区分 model、server、none；模型文本经服务端编辑也必须说明修改。历史记录无该信息时显示未知，不倒推为已采用。

归因在实际输出/决策边界产生，不能仅从 finish_reason 推测。覆盖普通流式正文、延迟输出采用、产品/知识库确定性替换、因计划继续而抑制候选，以及失败/取消的已有部分输出。无模型调用的收尾不伪造 LLM round，也不借用前一轮 ID。原候选仍留在详情中；不把服务端文本覆盖成模型产物。

事件只带有界元数据，不复制整段正文、工具响应或凭证。详情查询沿用现有会话授权和安全投影；前端详情展示处理状态、原因和来源，支持中英文与旧历史。新增观测不得替换执行异常或造成额外模型/工具调用。

## 验收

- 真实 SQLite Session：执行前 checkpoint → 新增 search 卡片 → 执行后 checkpoint → 取消/失败 → 新 Session 读取，卡片仍在；客户端伪造块继续被拒绝。
- 真实 execute_tool_batch 配合受控异步工具：首个所有权异常后，兄弟任务 finally 已完成，原异常保留；普通取消和正常并发不回归。
- 三种执行上限分别与未完成计划组合：无新增模型/工具调用，有现有事实总结和待办说明，最终状态仍为 limit_reached。
- 真实输出路径产生归因事件，经白名单/账本/详情 DTO 到前端；覆盖模型采用、服务端替换、候选抑制、旧历史与失败降级。
- 目标 pytest、Vitest、Ruff、前端静态检查/构建和 git diff --check；独立审查当前改动。
- 新增函数式 pytest 回归进入既有 Linux/Windows CI pytest 入口；不减少现有检查或放宽超时。
- 不将自动化隔离验证描述为 dev 或真实浏览器/模型验收。
