# LLM 搜索策略与引用完整性

用户已确认四项共同交付：多角度多批检索、扩大结果获取并筛选、证据不足继续与引用修复、LLM 控制搜索策略。沿用现有 Agent loop 和工具执行器，不引入额外框架。

## 实施边界

- 通过同轮多个独立 web_search 调用实现并行批次，保留逐调用事件、结果与全局引用编号。
- 工具暴露 count，默认10、范围1–20。服务端仅约束资源，不再按 quick_fact/后续检索把数量压成3。取消相似词与未读候选造成的提前限制，保留真正重复请求与全局调用预算。
- 提示词指导模型按证据需求选择角度、语言、来源、批次和停止时机；删除普通问题最多两次搜索、只能同语言和必须当前年份的旧规则。未指定时效不再强制最近一周。
- 结果合并沿用现有URL去重和全局来源编号，正文摘要受上下文容量限制；读取原始报道和官方资料优先由模型决策，来源不足不伪称已核实。
- url_read接收运行级编号，Observation与source_refs一致；不猜测重写已存在的历史[U1]。

## 验收

1. 单元与集成验证模型count经过真实参数准备到provider不被意图覆写，旧动态配置不会维持3/5条限制。
2. 事件屏障验证同轮2–4个搜索真正并发；后续批次和第三次普通搜索可执行，取消及全局预算仍有效。
3. 搜索后读同URL复用编号、新URL新编号，持久化映射和最终引用一致。
4. 真实原题“英伟达投资Perplexity意味着什么？”核对关键词、数量、原始来源、深读、最终事实与引用，以及简单天气查询回归。真实产品验收需已授权部署后的既有登录Chrome页面，不用模拟轨迹替代。
