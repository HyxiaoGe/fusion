# 工具载荷和结果可观测性修复

## 契约

- 用户希望 trajectory 展示工具实际查询参数与业务返回，避免审计白名单把城市、正文等普通数据整体省略。
- 在隔离分支 `codex/trajectory-tool-details` 实现并完成代码验证；本地交付后用户明确要求“发布吧”，继续 PR/CI、合并、dev 部署和真实验收。
- 不改 Agent 执行参数、模型上下文、SSE 账本、权限或数据库结构。仅在既有 `ToolCallLog.extra_metadata` 保存独立工具详情快照，详情按需读取；审计摘要维持原契约。
- 普通业务字段保留，明确凭据定点遮盖，大小限制和脱敏分别标记。旧日志保留原数据，并提示只记录了摘要，不伪造完整详情。

## 实施

1. 先添加失败回归：真实 handler 日志写入 → SQLite 持久化 → 新 Session 查询，涵盖天气/MCP、网页正文、凭据、错误、超长返回、精确关联和历史兼容。
2. 添加轻量、有界、纯数据的工具快照处理函数，由独立子代理实现并验证；主代理接入统一日志写入与详情查询。
3. 前端使用已有载荷/结果展示和截断提示，补充历史摘要与损坏详情的明确提示。
4. 运行定向后端/前端回归、审计与鉴权回归、静态检查和必要构建，安排独立 P0/P1 审查，记录交付层级。

## 验收与风险

- 新调用的实际业务参数、返回正文在重新查询后可见，空对象不是缺失；凭据遮盖不得改变执行侧对象。
- 大结果保留可读前部并标记截断；不混入脱敏字段。
- 历史摘要正常读取并提示限制；损坏的新快照明确降级。
- 现有会话/Run/tool_call_id 鉴权和精确关联不变，管理员审计不暴露新快照。
- 存储增量按每次快照上限控制；回滚代码即可恢复旧读取，新增 JSON 由旧代码忽略，无数据迁移或删除。
- 线上真实调用和浏览器刷新待本修复获得发布授权后验收；本地不启动 Fusion 服务。
