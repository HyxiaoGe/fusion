# Dev API 验收

遵循仓库根 `fusion-acceptance`。复用用户已明确的真实验收范围，不为必要场景逐次确认；只调查、只改代码或只推 PR 的请求不自动授权写入 dev 和收费调用。

- 先从当前路由/schema 确认 payload、认证、端口和可用模型 alias，不使用固定历史模型或旧端点模板。
- 凭据只从已授权的安全来源进入进程环境或受控客户端，不拼入命令文本、脚本仓库、URL、日志或报告，关闭 shell trace。
- 选择能验证本次问题的最小场景，标记本轮资源和停止条件；健康成功只是前置条件。
- 正常流式请求必须实际消费到目标事件和终态。断线、停止、失败或预算耗尽按各自预期判断，不能用 `timeout` 后忽略错误代替成功。
- 重连/恢复/停止只操作本轮归属明确的资源，核对目标 message/run 身份。按授权范围清理，未清理时记录残留。
- 记录脱敏标识、目标事件、终态和相关历史/恢复结果；不要保存完整用户正文或凭据。需要页面行为的结论还需既有 Chrome 标签上的真实消费证据。

API 或服务证据不足时准确说明，不能用数据库已有内容证明浏览器已收到。不得直接修改 dev 代码或配置来绕过 Git 发布流程。
