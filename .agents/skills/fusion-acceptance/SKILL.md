# Fusion 真实验收

使用当前仓库根 AGENTS.md，从本次预期行为选择最小充分场景。代码测试、运行版本、真实用户路径和用户亲自确认是不同证据。

用户指定的工作树优先；当前目录不是 Git 仓库时，从本 skill 的真实路径定位所属仓库并核对 remote。运行环境的版本仍需独立核验，不能由该工作树 HEAD 推断。

## 条件与授权

- 复用本次已明确的环境与验收授权。只调查或只写代码时不创建真实会话、不调用收费模型；用户已授权真实验收时，其必要场景不需要逐个申请。
- 真实页面只复用用户已打开且匹配的 Chrome 标签，不得创建新标签、窗口或隔离目标。找不到时报告具体页面缺口，继续代码、日志和其他已授权核验，不将缺口扩大成整个任务停工。
- 用户要求本地效果时，先核对现有运行入口与真实 API、认证及数据依赖。服务必须脱离临时会话持续运行，独立检查监听、HTTP、托管方式和日志；用户明确结束前保持运行。调试重启后恢复服务并复核。
- 凭据来自已有授权的安全来源，不写入 skill、仓库、命令文本或报告。必要写入仅限本轮测试资源；清理数据也应在授权范围内。

## 按故障选择证据

| 变化 | 最有区分力的检查 |
|---|---|
| 普通页面交互/视觉 | 自然操作、即时反馈、相关网络与控制台；视觉判断基于实际页面 |
| SSE、重试、停止、切换会话 | 实际消费事件，核对任务归属、终态、后续可发送及刷新恢复 |
| Agent/联网回答 | 自然问题、真实工具结果及可读来源正文、最终回答与持久化；成功状态或 URL 本身不算依据 |
| 文件/图片 | 用户提交入口、文件关联与处理状态、实际模型输入、展示和刷新；日志或模型自述只是补充 |
| 发布/回滚 | 当前运行版本与目标匹配、依赖健康及受影响业务路径 |

记录复现输入、预期/实际、URL 或会话/run 标识、相关网络/终态和刷新结果；范围按本次行为决定，不强制给所有小改动跑全套。服务事件顺序不能证明浏览器网络帧到达顺序，需客户端证据才下该结论。

问题仍能复现就回到定位。只有已执行的路径可写“通过”；条件缺失写“未验证”，真实失败写“失败”。代理验证完成不替代用户验收完成。
