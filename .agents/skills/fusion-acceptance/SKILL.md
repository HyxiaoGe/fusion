# Fusion 真实验收

使用当前仓库根 AGENTS.md，从本次预期行为选择最小充分场景。代码测试、运行版本、真实用户路径和用户亲自确认是不同证据。

用户指定的工作树优先；当前目录不是 Git 仓库时，从本 skill 的真实路径定位所属仓库并核对 remote。运行环境的版本仍需独立核验，不能由该工作树 HEAD 推断。

## 条件与授权

- 复用本次已明确的环境与验收授权。只调查或只写代码时不创建真实会话、不调用收费模型；用户已授权真实验收时，其必要场景不需要逐个申请。
- 真实页面按下方 Chrome 路径复用已有登录态；用户明确指定其他浏览器或隔离验收环境时，以本次选择为准。
- 用户要求本地效果时，先核对现有运行入口与真实 API、认证及数据依赖。服务必须脱离临时会话持续运行，独立检查监听、HTTP、托管方式和日志；用户明确结束前保持运行。调试重启后恢复服务并复核。
- 凭据来自已有授权的安全来源，不写入 skill、仓库、命令文本或报告。必要写入仅限本轮测试资源；清理数据也应在授权范围内。

## Chrome 已有标签的控制路径

1. 先阅读当前浏览器工具返回的 API 文档。当前桌面入口是 `mcp__cua_repl`：用户引用具体标签时直接按引用绑定；否则用 `cua.getState()` 枚举，确认 `type=extension`、`family=chrome`，按 URL、浏览器配置与任务上下文选择已有标签。多个候选无法消歧时才询问，不猜 browser/tab ID。
2. 用当前文档提供的现有标签绑定接口接管同一标签（当前为 `cua.getTab(...)`），读取页面并核对 URL、登录状态与目标会话。后续复用该绑定；不能仅凭 Chrome 进程存在、扩展安装或列表中出现 URL 就声称页面已可操作。不要照搬历史 `claimTab` 等调用，除非本次文档确实提供了对应接口。
3. 网页内容使用绑定标签的 AX/DOM、定位器及页面截图操作；操作后读取最新状态验证结果。`cua_repl` 同时提供浏览器和原生应用控制，工具名称不代表必须操作整个桌面。只有浏览器接口无法处理的原生对话框等具体步骤才使用原生应用控制，完成后回到原标签；扩展断连不能成为切换到桌面操作的理由。
4. 扩展内提供的 Playwright 定位器、控制台或受控 CDP 能力可以按当前文档使用，需要的权限按工具要求处理。独立 Playwright MCP/CLI、Chrome DevTools MCP 或其他 skill 的启动流程不能自动替代该连接，更不能为获取登录态新启 Chrome/Chromium、创建 profile、调试端口或隔离 CDP 目标。仓库自带自动化测试仍按测试环境运行，其结果不替代现有登录态验收。
5. 标签失效、扩展断连或缺少目标时，在已选 Chrome 中重新枚举一次；仍无法绑定就说明具体缺口与必要的连接恢复动作，继续其他已授权检查。不得通过新进程、新窗口、新标签、内置浏览器或复制 cookies 绕过。用户主动停止浏览器控制时尊重停止，不自动重连继续。

浏览器选择和已有登录态是执行约束，不要求用户每次重申或提供 `@Chrome`。按本次工具文档适配 API，不把临时 browser/tab ID 写入规则。产品设置与连接故障可查[官方扩展说明](https://learn.chatgpt.com/docs/chrome-extension)，不把修改权限或重启浏览器当作默认前置步骤。

## 适时交给用户的步骤

- 已有证据表明某个步骤由用户直接操作明显更快时，例如登录/授权、难以稳定自动化的拖拽或用户眼前即可判断的视觉效果，交接这个最小步骤，不持续消耗时间和配额尝试等价绕路。可用标签接口快速完成的普通点击、输入和读取仍自行执行。
- 交接时给出具体页面、最少操作、预期现象和需要反馈的结果；用户不必接手整套测试。等待期间继续独立核验，用户反馈后复用原标签/任务状态，补齐能自行验证的部分，不重复询问已有授权。
- 记录证据来源：用户反馈、代理直接观察或自动化检查。交接后尚未收到结果就是待验证；用户完成一个步骤不代表全部验收通过。

## 按故障选择证据

| 变化 | 最有区分力的检查 |
|---|---|
| 普通页面交互/视觉 | 自然操作、即时反馈、相关网络与控制台；视觉判断基于实际页面 |
| SSE、重试、停止、切换会话 | 实际消费事件，核对任务归属、终态、后续可发送及刷新恢复 |
| Agent/联网回答 | 自然问题、真实工具结果及可读来源正文、最终回答与持久化；成功状态或 URL 本身不算依据 |
| 文件/图片 | 用户提交入口、文件关联与处理状态、实际模型输入、展示和刷新；日志或模型自述只是补充 |
| 发布/回滚 | 当前运行版本与目标匹配、依赖健康及受影响业务路径 |

记录复现输入、预期/实际、URL 或会话/run 标识、相关网络/终态和刷新结果；范围按本次行为决定，不强制给所有小改动跑全套。服务事件顺序不能证明浏览器网络帧到达顺序，需客户端证据才下该结论。

问题仍能复现就回到定位。只有已执行的路径可写“通过”；条件缺失写“未验证”，真实失败写“失败”。代理验证完成不替代用户验收完成。
